# SpentSmart — Deep Audit (read-only)

Repo: `Ujjwaljain16/SpentSmart` · HEAD `773c901` (2026-10-16) · 66 commits · cloned to a temp dir, **nothing modified, nothing installed, no repo code executed**.
Method: every tracked source/config/doc file read line by line (103 tracked files; ~12.6k TS/TSX lines + Kotlin/Swift/config), plus cross-file greps, git-history scan, `npm audit --package-lock-only`, and standalone micro-benchmarks I wrote myself (not repo code).

---

## 1. What it is, and how it works

**Product:** an Android-first, "local-only" UPI expense tracker (Expo SDK 54 / RN 0.81 / TypeScript / expo-router). The user scans a UPI QR (or types a payee), picks a UPI app, pays *inside that other app*, comes back, and answers "did it go through?". Everything lands in AsyncStorage as JSON.

**Flow, as implemented**

```
Scanner ─parse QR→ /payment ─(save "pending" record)→ launch PSP app (native module / lokal launcher / GPay-QR-share hack)
   ▲                                                        │
   │  AppState "active" after ≥5 s away → ConfirmationModal │
   └── "Yes, Paid" → saveTransaction(status:'pending') ◄────┘
Home focus → if any unresolved pending in last 24h → push /recover-pending
```

**Layers:** `app/` screens (call services directly) → `services/*` (AsyncStorage JSON blobs, analytics, PDF export, UPI launching) → `modules/upi-intent` (Expo native module: Kotlin real, Swift/web = untouched template). Contexts: theme + security (biometric lock, privacy mode). No state library, no data layer, no tests, no CI.

**Storage keys (10, three naming schemes):** `@upitracker_transactions|_monthly_budget|_categories|_pending|_patterns|_user_upi|_user_name|_bio_lock|_privacy_mode|_theme|_last_backup`, `@spentsmart_onboarding_complete|_user_profile`, bare `pending_transactions`, `preferred_upi_app`.

## 3. Findings

Severity: **C** critical (data loss / false privacy promise / ship-blocker) · **H** high · **M** medium · **L** low.
"Verified" = reproduced with my own snippet or unambiguous from code; "Needs device" = plausible from code but I did not run it.

### 3.1 Critical

**C1 — Silent total data loss path in storage** — `services/storage.ts:12-23, 39-74`
`getAllTransactions()` swallows *any* error (JSON parse failure, AsyncStorage read failure) and returns `[]`. `saveTransaction/update/delete` then do read-modify-write on that array and `setItem` the result → **one transient read failure + one save = entire history overwritten with a single row.** Combined with the AsyncStorage size cliff (≈4.8k txns) this is a real upgrade-path data-loss bug. Also **no mutex**: two concurrent writers (e.g. deep-link callback + modal confirm) interleave and one write is lost (same pattern in `pending-manager.ts:21-97`, `category-storage.ts`). No schema version, no backup/restore (docs: "Backup (Planned)").
*Fix:* move to `expo-sqlite` (rows, indexes, transactions, migrations; SQLCipher for at-rest encryption), single write queue, never write after a failed read.

**C2 — Privacy promises contradict the code (also a Play-Store policy risk)**
| Claim (README / PRIVACY.md / Privacy Dashboard / docs) | Reality |
|---|---|
| "Your data never leaves this device", "no network calls for user data", "Internet: not accessed" | `services/silent-qr-share.ts:41-48` **GETs `https://api.qrserver.com/…?data=<upi://pay?pa=…&am=…>`** → your payee VPA, name, amount and note go to a third party, in plaintext-logged URL, on every GPay pay tap |
| "No contacts access" (`privacy-dashboard.tsx:364`) | `READ_CONTACTS` requested; `manual-entry.tsx:40-47` calls `getContactsAsync` (loads the **entire address book into memory**) only to check `data.length > 0`; the system picker needs no permission at all |
| "No analytics or tracking", notifications "for budget alerts only" | `expo-updates` phones home to `u.expo.dev` (policy mentions Expo only vaguely); notifications are 2 hard-coded daily reminders, no budget alerts exist, no opt-out |
| Clipboard not mentioned | `intent-monitor.ts:47-77` reads the clipboard on **every app resume** (Android 12+ shows the "pasted from clipboard" toast) |
| "Storage: never requested" | `expo-media-library` permission requested in `QRPaymentGenerator.tsx:153`; not declared/justified in `app.json` |
| "Delete all data" (`privacy-dashboard.tsx:71`, `settings.tsx:81`) | `clearAllData()` removes **only** the transactions key — categories, budget, profile, pending list, patterns, preferred app, lock settings survive (the dialog even says "categories" are deleted) |
| "Never leaves device" | Android Auto-Backup is not disabled in `app.json` (Expo's default template leaves it on) → AsyncStorage DB can be uploaded to the user's Google Drive backup *(Needs device: inspect prebuilt manifest)* |
| "Docs: INTERNET permission BLOCKED" (`CODEBASE_ANALYSIS.md:100`) | no `blockedPermissions` anywhere; INTERNET is present |

**C3 — Core "pay" path may not pass payment details to the PSP app** — `services/upi-app-launcher.ts:108-139`
`openUPIApp(appId, url)` **never uses `url`**. With the native module present it calls `launchAppByPackage(pkg)` = launch the app's *home screen* (`getLaunchIntentForPackage`). PhonePe/Paytm/etc. open empty; GPay is handled by the QR-image-share hack (and falls back into the same function). The user then re-enters the payee by hand while SpentSmart believes a payment was initiated and records amount/payee that may not match what was paid. (QRPaymentGenerator's `UpiAppLauncher` path *does* pass the URL for PhonePe/Paytm; `payment.tsx` doesn't use it.) *Needs device confirmation — but the code path is unambiguous.*

**C4 — "Decide Later" is a redirect trap** — `app/(tabs)/index.tsx:46-50` + `app/recover-pending.tsx:143-149`
Home pushes `/recover-pending` on **every focus** while any pending (< 24 h, unresolved) exists. "Decide Later" does `router.replace('/(tabs)')` → Home focuses → pushes `/recover-pending` again. The only exit is to resolve every item. Resolved ones are never purged either; `MAX_PENDING = 5` slices *including resolved*, so unresolved items can be evicted (`pending-manager.ts:15,30`).

### 3.2 High

**H1 — Unauthenticated deep links can forge data** — `app/upi-callback.tsx:28-50`, `app.json:35-49`, `services/intent-monitor.ts:29-45`
- `spentsmart://upi-callback?status=success&am=999999&pa=x&pn=Salary` from any app/web page **records an income transaction** (no correlation with a tracked `tr`; "duplicate protection" only works if the attacker reuses `tr`).
- `spentsmart://payment?upiId=…&payeeName=Amazon&amount=…` opens the pay screen pre-filled with an attacker-chosen name (name is never verified).
- `payment.tsx:50-52`: `JSON.parse(atob(params.rawParams))` is unguarded → malformed link = crash.
- App declares an intent-filter for the **`upi` scheme** (`autoVerify` is meaningless for custom schemes), so SpentSmart shows up as a "Pay with…" target and `getUPIApps` (`UpiIntentModule.kt:144`) lists **itself** as a UPI app.
- `handleDeepLink` treats *any* URL containing `tr=` as a callback (`"…?str=1".includes("tr=")` → true, verified).

**H2 — Biometric lock is weaker than it looks** — `contexts/security-context.tsx`, `app/_layout.tsx`, `settings.tsx:205`
- Toggle enables the lock with **no auth challenge** and only checks `hasHardware`, not `isEnrolledAsync` → a user with no enrolled biometric/credential can lock themselves out permanently (only recourse: clear app data = lose everything).
- `isUnlocked` initial `true` (`security-context.tsx:24`) → content renders for a frame before settings load.
- Lock only after 120 s in background; no screen-capture/app-switcher protection (no FLAG_SECURE / `expo-screen-capture`).
- Privacy Mode is incomplete: `InsightsGrid` (amounts), `charts.tsx` category amounts, `recover-pending`, `pending-transactions`, `ConfirmationModal`, `analytics-detail` per-comparison amounts are **not masked**.
- While locked, `initIntentMonitor()`/reminder scheduling still run and can `router.push` into an unmounted navigator (`_layout.tsx:99-111`).
- Lock/background effect depends on `lockApp` (new function each render) → re-subscribes every render and resets its local `backgroundTime` (`_layout.tsx:56-78`).
- Data at rest is plain-text JSON; `CODEBASE_ANALYSIS.md` lists SecureStore as "roadmap".

**H3 — Money handled as binary floats, weak validation** — `storage.ts`, `manual-entry.tsx:69`, `parser`
- `parseFloat("-50")` passes `!parsedAmount || isNaN` → **negative amounts saved** (verified); `"12abc"`→12, `"1e9"`→1,000,000,000; no max, no 2-dp rounding, `0.1×10 = 0.9999999999999999` (verified). Use integer paise.
- `amount: amount || paymentData.amount || 0` can persist a ₹0 transaction.
- Manual "Pay Now" with empty UPI ID routes to `/payment` where `upiId = params.upiId || 'unknown@upi'` (`payment.tsx:44`) → app builds a pay URL to a **placeholder VPA**. `isValidUPIId` exists but is **never called**; receive-profile only checks `includes('@')`.
- The "Transaction Saved" alert appears *before* anything is saved (`manual-entry.tsx:80`).

**H4 — QR parsing corrupts signed/merchant QRs** — `services/upi-parser.ts:86-95`, `constants/upi-config.ts:29-74`
`pair.split('=')` + `if (key && value)` **truncates every value containing `=`** — verified: `sign=AbC123xyz==` → `AbC123xyz`, `tn=a=b` → `a`. Merchant QRs carry `sign`/`orgid`/`mid` and are "replayed as-is" via `rawParams`, so a truncated signature makes the PSP reject it. Also: for a static-amount merchant QR the user-edited amount field is ignored by the replay but *recorded* by SpentSmart; unreachable code after `return` (`upi-config.ts:100-124`); two divergent `parseUPIQRCode` and two `buildUPIUrl` implementations (`services/upi-parser.ts`, `constants/upi-config.ts`, `silent-qr-share.ts`).

**H5 — The "verification" system is dead; every transaction stays `status:'pending'` forever** 
`saveTransaction` hard-codes `status:'pending', confidence:50, verifiedBy:'user'` (`storage.ts:66-68`). `updateTransactionStatus`'s only caller is `app/pending-transactions.tsx`, whose data source (`payment-verification.ts → addPendingTransaction`) **is never called anywhere**. `calculateConfidence`, `getSmartPromptMessage`, `verifyPayment` (a stub returning `true`), `rawQr`, `sanitizedUpiUri`, `upiTransactionId`, `PendingManager.getConfidence` — all dead. Meanwhile the live confidence heuristic (`usePaymentConfirmation.ts`) rewards *any* absence ≥25 s with 95 % (no upper bound: lock the phone for 3 h and it says "very high") and contradicts the dead one (>120 s = −10).
*Real fix:* use the UPI spec's own result — launch with `startActivityForResult` and read `Status/txnId/txnRef/responseCode` (what `@lokal-dev/react-native-upi-app-launcher` already provides). That gives genuine confirmation without SMS, and makes the whole heuristic layer unnecessary.

**H6 — Build / release blockers**
- `app.json:24-25` references `android-icon-background.png` and `android-icon-monochrome.png`; both were **deleted in git history** → fresh-clone prebuild/EAS build will fail *(Needs build to confirm)*.
- `index.js` imports `./App` (doesn't exist, `main` is `expo-router/entry`) — orphan; `reset-project` script points to a deleted file.
- `"reactCompiler": true` at top level of `expo` is not a valid key (belongs under `experiments`; `babel-plugin-react-compiler` isn't installed) → silently a no-op while the README/docs imply optimisation. `typedRoutes` off → 8 `as any` route casts.
- `eas.json`: `production` has no `channel`, no `autoIncrement`, empty `submit`; `runtimeVersion: appVersion` + OTA means JS can be pushed to builds with different native code; no update code-signing.
- Branding drift: iOS permission strings, Face-ID/auth prompt ("Unlock ExpenseTracker"), PDF header ("UPI Tracker"), `package.json` repo URL, privacy-policy link in Settings → all still `ExpenseTracker`.
- No crash reporting (`GlobalErrorBoundary` has a TODO; it shows raw `error.toString()` to users and only catches render errors).
- 64 npm advisories (see scorecard).

## 4. Architecture assessment

| Area | Today | Gap |
|---|---|---|
| Layering | Screens call `services/*` and AsyncStorage directly; business rules (matching pendings, month math, confidence) live in screens/hooks | No domain/repository layer, no single source of truth, no cache → every screen re-reads & re-derives |
| Data | One JSON blob per entity, floats, no ids for payees, no migrations | SQLite (+SQLCipher), integer paise, versioned migrations, indexed by `timestamp`/`category`/`payee` |
| State | `useState` per screen + 2 contexts | A small store/query layer (e.g. TanStack Query over repo, or zustand) with invalidation on writes (replaces focus-reload + the unused `DeviceEventEmitter`) |
| Payments | Launch-and-guess + heuristics | UPI result intent (`startActivityForResult`) → deterministic status; explicit state machine `created→launched→{success,failure,submitted,unknown}` |
| Native | Kotlin module with real value but scaffold residue, over-broad FileProvider, wrong typings | Slim module: `getUpiApps`, `launchUpi(url,pkg)→result`, `share…` removed; typed API; iOS/web removed or implemented |
| Security | Plain JSON, UI-level lock | Encrypted DB, key in Keystore (SecureStore), lock on cold-start before any data read, FLAG_SECURE/blur snapshot, backup disabled |
| Quality | 0 tests, no CI, ESLint default only | Vitest/Jest on services, RNTL on screens, Maestro/Detox on pay flow, CI gates |
| Release | Manual EAS, unsigned OTA | channels per env, update code-signing, staged rollout, Sentry + source maps, store-compliant data-safety form |

## 5. Recommended path to "really, really best" (ordered; nothing started)

**Phase 0 — stop the bleeding (≈1–2 days, small diffs)**
1. Never write after a failed read; add a write mutex; backup-before-write (C1).
2. Break the recover-pending loop (snooze timestamp + purge resolved) (C4).
3. Validate amounts (>0, ≤ cap, 2 dp), validate VPAs, remove `unknown@upi` (H3).
4. Fix `=`-truncating parser; unify the two parsers/builders (H4).
5. Remove the `api.qrserver.com` call (generate QR locally with the already-installed `react-native-qrcode-svg`) (C2).
6. Remove contacts permission (use the keyless system picker only); correct the Privacy Dashboard/README/PRIVACY.md text; make "Delete all data" actually delete everything.
7. Restore/replace the two missing adaptive-icon files; delete `index.js`; fix `reactCompiler` key; rename remaining "ExpenseTracker".
8. Lock down deep links: ignore `upi-callback` unless `tr` matches a tracked attempt; validate/limit params; guard `atob/JSON.parse`; remove `autoVerify`.
9. `openUPIApp` must actually pass the URL (or use the result-intent launcher) (C3).

**Phase 1 — data layer (≈1 week):** `expo-sqlite` repo, paise ints, migrations, import from old AsyncStorage (one-time), pagination, indexed queries, remove N+1, cached categories; SQLCipher key in SecureStore; disable Android backup.

**Phase 2 — payment correctness:** state machine + result intent; delete `payment-verification.ts`, `local-upi.ts`, the heuristic hook; one pending store.

**Phase 3 — quality infra:** typed routes, strict lint (no-console, no-explicit-any, exhaustive-deps), Prettier, Vitest for `services/` (parser, analytics periods, budget, storage failure-injection), RNTL for screens, Maestro for scan→pay→confirm, GitHub Actions + `npm audit --omit=dev`, Dependabot, Expo SDK upgrade.

**Phase 4 — UX/perf/a11y/release:** theme tokens + shared primitives (kill 114 hex literals/duplicated styles), accessibility labels, FlashList for history, debounce search, split 500-700-line screens, i18n-ready strings, Sentry + sourcemaps, EAS channels + update signing, store data-safety form.

**Suggested targets after Phase 1–3:** save/update p95 < 20 ms at 50k rows on a mid-range Android; cold start → Home < 1.5 s; 60 fps history scroll at 10k rows; 0 high/critical advisories in prod deps; ≥ 80 % service coverage; 0 `any` in `services/`; 0 console in release; every interactive element labelled.
